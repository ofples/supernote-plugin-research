# SuperTask native interaction implementation goal

Activated 5 October 2026 at the user's request. Specification: [NATIVE_INTERACTIONS.md](NATIVE_INTERACTIONS.md), based on the supplied native To-Do screenshots and the reviewed clickable prototype. Baseline: validated beta.12, testing branch commit `5ec9531`; design checkpoint `31b518c`. This is an implementation goal, not a request for another planning-only pass.

## Objective

Implement the complete native-style SuperTask interaction redesign: inline contextual creation; row quick actions and full editing; multiselect bulk edits; completed tasks below active tasks without an Undo banner; dotted separators and simpler toolbars; offline project/collection management and synchronized task ordering; a reliable optional floating launcher and stricter optional gesture; OCR/AI title-description organization; immediate optimistic interactions without network or global input locks. Deliver reviewed separate draft PRs, an updated combined testing branch, a built/inspected beta, available Nomad verification and a precise remaining-checks handoff.

## Mandatory behavior

1. Keep useful smart views, This Note/On Device, plain project navigation and All projects beneath Projects. Use quiet dotted task/sidebar separators, an outlined selected sidebar entry, full-width collection rules and sufficient pen/finger targets. Preserve density, font scale and orientation support.
2. Simplify everyday chrome: Settings and Close at application level, current list/project name and … menu in the pane. Remove + New, + Batch and Show done buttons. Preserve lasso capture and multi-row review through their existing entry points; debug access moves into Settings.
3. Add an inline text composer with calendar and Add/Enter submission. Destination and date defaults follow the specification. Collection targets must be explicit. Keep focus, draft text and stable creation identity through asynchronous local saving; do not lose drafts on view changes. Empty drafts are disabled; only the affected draft is held during an unresolved local write.
4. Checkbox completes/reopens immediately. Body tap expands one row with Edit/pen, Date, Move, Priority, Up/Down where valid and Delete. Pen opens the full editor and returns to the same list/scroll state. Task selection is a separate explicit mode entered from … or long press: squares select rather than complete, row body also selects, and the contextual bar supports Move, Date, priority/labels/completion and Delete. Select all means the complete current active filtered list, including offscreen rows; completed selection is an explicit history context. Selected fields alone change.
5. Completed tasks appear in a collapsible bottom section with count and recent cached history, not a Show done button or completion Undo banner. Ordinary tasks reopen from their checked circle. Recurring history distinguishes occurrences and respects the existing restriction after first send; never mutate the next occurrence accidentally. Background history refresh does not remount or block the workspace.
6. New project is fixed below the scrolling sidebar list. New collection is available within a project. Project/collection … menus support rename/delete, offline where cached scope and permissions permit. Inbox is protected. Create/rename/delete dependencies and temporary IDs survive restart. Container deletion must make its effects on contained tasks explicit; Keep tasks uses acknowledged moves before parent deletion, while Delete tasks too needs explicit scope/count confirmation. Unknown offline descendants/history must not be silently destroyed or claimed retained. Respect workspace/shared permissions and preserve subtasks/descendant projects.
7. Manual Up/Down task ordering synchronizes with Todoist within a project/collection and sibling hierarchy, as explicitly confirmed. Today/Upcoming retain date grouping. Check the current official ordering contract, do not copy obsolete child_order assumptions, and preserve unrelated remote edits. Resolve temporary IDs and reconcile membership/order conflicts before sending.
8. Provide the proposed optional movable edge launcher using an isolated native bridge, alongside the normal toolbar route. Tap opens tasks, dragging repositions without launching, normalized edge position survives rotation, and Hide/disable removes it. Handle overlay permission, lifecycle, restart, focus, e-ink refresh, other plugin coexistence and precise pen handling. Never leave a full-screen pen lock or orphaned duplicate overlay. Implement a stricter optional multi-finger edge swipe using stable pointer identities and coherent concurrent movement; do not merely increase the finger count or lower travel thresholds. Gesture tuning needs actual hardware traces; safe rejection is preferable to a false launch.
9. Device OCR stays transcription plus deterministic first spaced-dash parsing into title/description; preserve later separators, hyphenated words, bullets, minus signs and wrapped-line provenance. AI may organize a concise title and supported explanatory description without inventing facts. Preserve explicit metadata rules and independent manual title/description overrides. Review/Undo remain available for AI proposals. Retain opt-in calls, concurrent OCR, cancellation/timeout/fallback, private credentials and no auto-save.
10. Interactions render intent immediately, then secure the durable local transaction independently. Distinguish Saving locally, Saved on device/waiting to sync, Synced and attention. Never claim durability before commit. Per-task serialized/final intent and atomic bulk local mutations replace the global in-flight UI lock. Unrelated tasks, navigation, typing and menus stay usable. Known local failure rolls back only its overlay and retains a draft/retry; uncertain saves reconcile under the same identity. Account switching cancels old-account UI dispatch. No network request, OCR/AI operation, permission check or history refresh freezes the workspace.
